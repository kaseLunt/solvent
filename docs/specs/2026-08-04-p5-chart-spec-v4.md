# Solvent P5 — Final chart spec v4 (consolidated)

Provenance: solvent-design director rulings v1–v3, adversarial Codex review round 1
(owner-adopted in full), designer rebuttal, Codex round 2 convergence verdict
(owner-delivered 2026-08-04), final consolidation v4. This document supersedes
v1, v2 and v3 in full and stands alone. Two surfaces: the Book risk map
(`DensityMap` / `BookRiskMap`) and the Lab loss frontier (`LabFrontier`), plus
cross-surface correctness items.

---

## 0. Standing law notes (bind beyond this wave)

- **LAW-1 (repricing).** Newly entering eligible debt must never be derived by
  subtracting cumulative monetary points, because deeper shocks reprice
  already-eligible debt. Only the wire's first-observed account count may be
  called entry. Any future "incremental debt" view is blocked on a wire field,
  not a client subtraction.
- **LAW-2 (percent axes and engine separation).** Percentages are
  dimensionless, so a shared 0–100% axis across engine panels compares shape,
  never units, and does not create a forbidden cross-engine aggregate. Each
  panel must still name its own denominator.
- **LAW-3 (rendered pixels).** Chart geometry constants are RENDERED CSS
  pixels. SVG user units are not pixels under viewBox scaling. Every chart in
  this spec renders 1:1 from a measured container width, with a minimum width
  and horizontal scroll below it.
- **LAW-4 (semantics never float).** Floats may compute pixel positions only.
  Any value that decides a bin identity, a bucket, a threshold or a displayed
  number is exact integer or string work.
- **LAW-5 (exactness is reachable without a mouse).** A `<title>` is hover
  sugar. No number may exist only in a `<title>`.
- **BANKED:** the frontier third strip (blocked by LAW-1) and the bad/eligible
  ratio row (if revived: beside absolute exposure, qualified below a defined
  denominator threshold, filed as a composition ratio under materiality).

## 1. The section template (reusable, rolls product-wide)

| # | Slot | Content | Collapsible |
|---|------|---------|-------------|
| 1 | **HEAD** | identity, engine chip, as-of batch, unit | no |
| 2 | **STATE** | refusal, withheld engine, supersession, outpaced, walk failure, monotonicity violation, source-filter semantics, shock-sampling caveat, independent-scale warning, coverage line | **no** |
| 3 | **ANSWER** | one computed sentence, 14px, `--ink` | no |
| 4 | **VISUAL** | the chart. Direct labels and axis ticks only | no |
| 5 | **LEDGER** | exact numbers, column or row aligned to VISUAL, unrounded, HTML | no |
| 6 | **METHOD** | one 12px line: encoding, unit, as-of | no |
| 7 | **FORENSICS** | `<details>` closed by default: decompositions, full identities, verbatim wire caveats, per-reason aside breakdown | yes |

- **R1** Exact money never floats inside VISUAL. Axis ticks are the only
  exception; a tick is a ruler, not a value.
- **R2** LEDGER geometry is generated by the same scale module as VISUAL.
  Shared code, not shared intention.
- **R3** FORENSICS may never hold a refusal, a withheld count above zero, a
  supersession, or any unknowable.
- **R4** ANSWER is computed from the data VISUAL renders.
- **R5** LEDGER never rounds, and distinguishes a computed zero (`$0`) from an
  unknowable or unserved value (em dash) in every cell.
- **R6** Everything that qualifies the visual renders before the visual.
- **R7** Material missingness is always visible. The per-reason breakdown may
  collapse; the coverage line may not.
- **R8** Token is `--ink` (there is no `--ink-1`).

## 2. Risk map — final treatment

**RM-1. Ordered compressed sub-$1 lane.** Piecewise x scale: exponents below 0
map into a 48 rendered-px lane at the left; exponents at or above 0 map
log-linearly across the remainder. Lane gap 14px. Log domain `[0, xMaxExp]`;
lane domain `[xMinExp, 0]`. Order inside the lane is preserved. No interior
ticks, no interior gridlines, one axis label `<$1`.

**RM-2. Break glyph, visible.** At the lane's right edge: a vertical hairline
`.axisBreak { stroke: var(--ink-2); stroke-width: 1; stroke-dasharray: 2 3 }`
across the plot height, plus two parallel 10px diagonals 5px apart crossing the
axis baseline in the same token. Never `.refLine`, which is reserved crit
vocabulary. `--ink-2` rather than `--line` for WCAG 1.4.11.

**RM-3. Lane visibility.** Render the lane iff `xMaxExp > 0` and at least one
mark sits below `$1`. If every mark is sub-$1, no lane and no break: a plain
log axis over the true domain.

**RM-4. Tick policy.** One lane label `<$1`. True decades from `$1` up, thinned
by `stride = ceil(decades.length / 8)`. Axis title `debt (usd, log)`.

**RM-5. Cell encoding: count.** Opacity quantizes account count on four steps
at 1 / 10 / 100 / 1,000. Exact count and exact Σ debt both ride every cell
title and both appear in LEDGER.

**RM-6. Non-text contrast.** Ramp opacities become `0.30 / 0.48 / 0.66 / 0.85`
so the lightest nonempty cell clears 3:1 against `--panel` in both themes. The
selected cell additionally takes `stroke: var(--ink-2); stroke-width: 1`.

**RM-7. Marginal bars, common scale.** Right margin carries one horizontal bar
per band, length proportional to that band's exact Σ debt, all seven on one
common scale from zero, `.barFlow`. Zero draws no ink. Each bar carries its
exact Σ in its title. `MARGIN.right = 80` (bar column 72 plus 8 pad). Exact
numbers live in LEDGER, so no money text sits in the SVG margin (R1).

**RM-8. Crit strip, unbounded dynamic lanes.** The breached row becomes a
dedicated strip. Sort crit descending by exact debt, ties by account. First-fit
pack into lanes at 8px pitch, mark 6×6 with `rx 1`, `.dotCrit`. Strip height
`= 8 + lanes × 8`, **uncapped**: lanes only grow under true x collision, and
the panel grows rather than making a mark unreachable. Mod-N lane reuse is
forbidden, and no cluster glyph is used, because every mark must be
individually hoverable and focusable. Jitter is forbidden: x is quantitative.
Vertical dodging is lawful because y carries no quantity inside a band row.

**RM-9. Numbered callouts.** Top 12 exposures by exact debt take numbered
callouts `1`–`12` at 12px mono beside their mark. Deterministic packing in
debt-rank order at a 16px exclusion radius per band. A callout that cannot be
placed clear takes a leader line: a 1px `--ink-2` hairline from the mark to the
nearest free position within 24px, drawn under all data ink. A callout that
still cannot be placed is not drawn and is counted in the overflow line. Every
one of the twelve is in FORENSICS regardless.

**RM-10. Exact bin index, no float in semantics (LAW-4).** `riskBins` currently
decides the semantic bin with `Math.floor(Math.log10(v) * 2)` while its own
header forbids floats outside geometry. Replace with integer arithmetic on
bigint units `u` at `d` decimals:

```
D      = digits(u) - 1 - d
xIndex = 2*D + (u*u >= 10n ** BigInt(2*digits(u) - 1) ? 1 : 0)
```

Verified: `u=3162,d=0` → 6; `u=3163,d=0` → 7; `u=46,d=6` → −9; `u=1,d=0` → 0;
`u=5,d=0` → 1. Float `log10` survives for px only.

**RM-11. Measured width (LAW-3).** ResizeObserver on the panel body, following
the `DataTable.tsx:131-143` precedent. Width clamped `[720, 1400]`, pre-measure
fallback 980, rendered 1:1 (`width` attribute equals measured px, viewBox
identical). Below 720 the frame scrolls.

**RM-12. LEDGER (complete exact equivalent).** An HTML region beneath the SVG
holding: (a) band totals, seven rows, exact count and exact Σ debt; (b) **every
nonempty bin**: headroom band, exact debt range from the bin's half-decade
bounds, account count, exact Σ debt; (c) the selected cell's detail when a cell
is active. Never collapsed.

**RM-13. Selection and keyboard.** Roving tabindex: one tab stop for the whole
grid, arrow keys move the selection, Enter or Space activates. Activation
renders the cell detail from the already-held full-book vector, with no new
request: exact count, exact Σ debt, exact range, and the cell's top 24 accounts
by exact debt with the remainder counted.

**RM-14. Accessible association.** `aria-describedby` points at the METHOD line
only. `aria-details` points at the FORENSICS region, and a visible `Exact data`
button moves focus to it.

**RM-15. Coverage line, always (R7).** Rendered in STATE on every render
including zero refusals. Per-reason breakdown may sit in FORENSICS.

**RM-16. Slot order.** HEAD, STATE (coverage line, source-filter semantics,
supersession, outpaced, walk failure), ANSWER, VISUAL, LEDGER, METHOD,
FORENSICS.

## 3. Loss frontier — final treatment

**LF-1. Two rows, one shock axis.** Row 1 Σ eligible debt `.barFlow`, row 2 bad
debt `.barCrit`. The inset crit bar is deleted: at the 1.5px floor it occluded
the flow bar, so `eligible $15,380 / bad $0.000046` was indistinguishable from
`eligible $0.000046 / bad $0.000046`. No third strip (LAW-1).

**LF-2. Heights and separator.** Row 1 plot 104px, row 2 plot 64px. A
full-width separator rule between them carries row 2's scale statement.
Deliberately unequal heights, separate tick sets, per-row direct labels and the
separator are four independent cues that the rows are on different rulers.

**LF-3. Linear scales, per row.** Bars encode magnitude from zero, so log is
forbidden. Each row has its own domain top from the ladder
`[1, 2, 3, 5, 10] × 10^k`, computed in the engine's integer unit as bigint.
Row 1 ticks `$0`, `top/2`, `top`. Row 2 ticks `$0`, `top`. Tick labels are
exact grouped strings such as `$2,000,000`. `MARGIN.left = 88`.

**LF-4. No money floats in the SVG (R1).** There are no per-bar value labels
and no in-SVG value strips. Exact values live in the LEDGER directly beneath,
column aligned.

**LF-5. Cliff line and label.** Dashed `.refLine` from row 1 plot top to row 2
baseline at the cliff bar's centre, painted before the bars so a hairline never
crosses data ink. Label in `.refLabel` at the top, anchored `end` when the
cliff sits in the right 40% of the plot, otherwise `start`.

**LF-6. Hit targets.** A transparent `.hitTarget` rect per sample per row, full
slot width and full row height, carrying step, exact Σ eligible debt, exact bad
debt, first-eligible count and cumulative eligible accounts. A 1.5px bar is not
a hover target.

**LF-7. Bad debt all zero.** When `peakBadDebt` is zero, row 2 is not drawn and
a stated-zero sentence renders in its place. An empty second row would read as
absent data.

**LF-8. LEDGER, transposed and share-scaled.** HTML grid beneath the SVG. Rows
are measures, columns are grid samples in chart order: `Σ eligible debt`,
`bad debt`, `first eligible on grid`, `eligible accounts`,
`collateral at risk`.

- **One column per GRID sample**, taken from the waterfall's own points, not
  per served point.
- Computed zero renders `$0`. A sample this engine did not serve renders em
  dash in every cell of that column plus `not served` under its axis tick. That
  is how a computed zero stays distinguishable from a hole with no floating
  labels.
- **No suppression.** Column width is `max(plotW / n, longestValueWidth)`,
  where `longestValueWidth` is **measured**, not estimated: a hidden mono probe
  of ten `0` glyphs yields `chPx` once, and
  `longestValueWidth = maxChars * chPx + 16`.
- **R2 shared geometry:** `app/lab/frontierScale.ts` is the single source. It
  takes `(measuredWidth, n, chPx, maxChars)` and returns
  `{ marginLeft, slot, plotW, x(k) }`. The SVG places bar centres at `x(k)`;
  the ledger renders `grid-template-columns: {marginLeft}px repeat(n, {slot}px)`.
  When `slot` exceeds the container, the SVG and the ledger scroll together
  inside one frame.

**LF-9. Measured width (LAW-3).** Same ResizeObserver pattern, clamp
`[640, 1280]`, fallback 960, rendered 1:1.

**LF-10. Accessible association.** `aria-describedby` to the METHOD line,
`aria-details` to the LEDGER, plus a visible `Exact data` control moving focus
to it.

**LF-11. Slot order.** HEAD, STATE (excluded engines, monotonicity violation,
held-flat, shock-sampling caveat, independent-scale warning), ANSWER, VISUAL,
LEDGER, METHOD, FORENSICS (verbatim `eligibility_note` and `at_risk_note`).

## 4. Cross-surface correctness

**CX-1. Net versus gross counts.** `cmd/api/p5_runbook.go:591` computes
`NewlyEligibleAccounts` as `ea.eligibleAccounts - eb.eligibleAccounts`, a
signed net delta, and the contract says so itself (`proof-contract.gen.ts:2737`:
"a NET count and also subtracts any flip back to healthy").
`LabBookPanel.tsx:137` calls it "Newly eligible accounts". Fixed by CX-2 and
CX-3, which must share no phrase.

**CX-2. Run-book card.** Label `Net change in eligible accounts`. Value always
signed: `+164`, `−3` with U+2212, `0`. Tone crit above zero; **default below
zero and at zero** (a favourable metric movement is not a favourable scenario).
Accounts are dimensionless, so no unit clause.

**CX-3. Frontier ledger row.** Label `first eligible on grid`, with the title
in the copy block. The accounts latch, the count does not, and at the unshocked
point this is the standing census.

**CX-4. Grouped money.** Promote `frontierView.labUsd` to `lib/book-format.ts`
as `renderUsdAmount(value: string | null, decimals: number)`, null to em dash,
otherwise `$` plus `groupDecimalString(formatUnits(...))`. Route
`LabBookPanel.money` (`:104`), `LabRealization.money` (`:29`) and
`frontierView.labUsd` through it. `renderNullableDecimal` has many non-money
callers and is not touched.

**CX-5. Risk-band distribution rename.** Display only; wire field
`hf_histogram` and all testids unchanged. Section heading, panel aria-labels
and the run-book pair aria-label all move to "risk-band distribution".

**CX-6. Percent-share bars.** Within one engine, `count / largestBucket` and
`count / engineTotal` differ by a constant factor, so the within-engine shape
survives the change. Bar length becomes **share of the named denominator on a
common 0–100% axis** with ticks at 0, 50 and 100. Row label stays
`{count} · {pct}%`, percent by exact integer arithmetic
(`count × 1000 / denominator`, truncated). Denominator is **debt-bearing
accounts with a finite comparator**, named on every panel. `infinite_count` and
`refused_count` render as explicit accounting rows beneath the bars, never
folded into the denominator silently. With the percent axis the two engine
panels may sit side by side in symmetric frames (LAW-2).
`LabRunBookDetail.tsx:92` already shares one scale across before and after and
is unaffected except for the axis change.

**CX-7. Typography floors (LAW-3).** Minimum **12 rendered CSS px** for all
chart text, and no chart text may be shrunk by viewBox scaling. Minimum
**4.5:1** contrast against `--panel` in both themes; axis labels move from
`--ink-3` to `--ink-2`, and if `--ink-2` misses in either theme the token
moves.

**CX-8. Signed deltas and near-zero percentages.** Any field whose wire note
says delta renders an explicit sign (`+`, U+2212, bare `0`). No percentage
renders against a zero denominator; a percentage above 9,999% renders
`from near-zero`.

## 6. Acceptance checks (complete, final, self-contained)
